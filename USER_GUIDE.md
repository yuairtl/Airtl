# Airtl User Guide

This guide explains how to install Airtl, select a project, use its Vivado and OpenCode integrations, and configure AI prompts and skills. For Chinese, see [使用指南.md](使用指南.md).

## 1. What Airtl does

- Browse HDL module hierarchies in the VS Code sidebar, open module definitions, and view XDC files.
- Use the **Block Design View** to visualize module scopes and connections from Vivado BD projects or plain HDL logic. A `.bd` file is optional.
- Send tasks such as module explanations, IP port lookup, simulation, synthesis, implementation, and bitstream generation to an AI tool.

Vivado does not need to be running to browse existing project files. AI workflows require an AI tool. Running Vivado simulation, synthesis, implementation, or bitstream generation requires Vivado installed on your computer.

## 2. Prerequisites

| Item | When needed | Details |
| --- | --- | --- |
| VS Code | Required | VS Code 1.126.0 or later is recommended. Older versions have not been fully tested; this is not a confirmed minimum requirement. |
| Airtl VSIX | Required | The current release targets Windows x64. GCC/MinGW is not needed to install the extension. |
| Vivado | To run simulation, synthesis, implementation, or generate a bitstream | Install Vivado locally and make sure the project has the required license. After changing a BD, regenerate its HDL before refreshing Airtl. |
| OpenCode and a model | To use AI features | OpenCode CLI is the default; 1.18.35 is the recommended, integration-tested version. Other versions have not been individually verified. Install the CLI, connect a model provider, and select a model. Provider charges may apply. |
| Prompt and skill content | To have AI follow Airtl workflows | Release files are placeholders and contain no ready-to-use task instructions. Fill them in or contact the developer for ready-made content. |
| Airtl core authorization | To use native core features | The compiled native core is managed under separate authorization terms. If an authorization message appears, check the logs and contact the developer. |

The VSIX includes Airtl's compiled native core but not its C++ source code. See [LICENSE](LICENSE) and [LICENSE-APACHE-2.0](LICENSE-APACHE-2.0) for the licensing boundaries. The current VSIX targets Windows x64; Linux requires a separately built and verified native package.

## 3. Install the extension

1. Download `airtl-<version>-win32-x64.vsix`.
2. In VS Code, open Extensions, select `...` in the upper-right corner, choose **Install from VSIX...**, and select the downloaded file.
3. Reload VS Code after installation.

## 4. Open a project and browse the source tree

1. Open the folder containing your Vivado project in VS Code.
2. In the left sidebar, open the view labeled **源码树** (Source Tree), then expand **工程来源** (Project Source).
3. Select a source type:
   - `.xpr`: preferred for an existing Vivado project;
   - Tcl: select a project Tcl script containing the top-level and source-file setup;
   - HDL source: if there is no `.xpr`, select an HDL file to use as the top-level source.
4. Click the refresh button in the Source Tree title bar to load the hierarchy and XDC constraints.
5. Click a module to locate its instantiation in the parent. Double-click it or use **Go to Module Definition** from the context menu to open its definition.

Airtl remembers the selected source for the current workspace. After switching or adding projects, select the source again under **工程来源** (Project Source) and refresh.

## 5. Use Block Design View and run Vivado workflows

### View module logic and connections

After you select a project source, open a module in the **Block Design View** to inspect its logic and connections. This view supports plain HDL projects as well as Vivado BD projects; a `.bd` file is not required for pure RTL. For a BD project, Airtl reads the `.bd` file and HDL generated by Vivado. Vivado does not need to be running to view files that have already been generated. After changing a BD, regenerate its output products/HDL in Vivado and refresh VS Code so the view reflects the updated connections and ports.

Open a module from the module tree to view its scope. The graph lets you inspect connections, open child modules, and use the available export or connection-editing actions.

### Run AI simulation, synthesis, implementation, or bitstream generation

1. Install Vivado and confirm that the project opens and has the required device/feature license.
2. Install the OpenCode CLI and make sure `opencode` runs in the VS Code terminal. Installing only the OpenCode editor extension for VS Code is not sufficient.
3. Follow the [official OpenCode documentation](https://opencode.ai/docs/) to connect a model provider (use `/connect` in the TUI) and select a model (`/models`). Airtl uses the `opencode` command by default and attempts to resume or create a session for the current project.
4. Configure prompts and skills as described in Section 6.
5. In Airtl's **工作流任务** (Workflow Tasks) view, click Simulation, Synthesis, Implementation, or Generate Bit. Airtl sends the project path and task instructions to the current OpenCode session. The AI operates on the local project and Vivado according to your configuration; OpenCode or the operating system may ask you to approve commands. Review the AI's plan and Vivado logs before accepting the result.

Airtl prepares and sends task context to the AI; the AI tool runs Vivado commands according to its configuration. Airtl does not provide a Vivado license and cannot guarantee that every project will pass simulation or implementation without project-specific work.

Vivado is automatically searched for under version folders in `C:\Xilinx\Vivado`, `D:\Xilinx\Vivado`, and `E:\Xilinx\Vivado`. If Vivado is installed elsewhere, set its paths in `C:\userconfig\rtlassistant\config.json`:

```json
{
  "vivado": "F:/Xilinx/Vivado/2025.1/bin/vivado.bat",
  "vivadoDir": "F:/Xilinx/Vivado/2025.1"
}
```

Keep any other existing settings in that file. The source tree and other non-AI features can still be used without OpenCode. To stop Airtl from trying to initialize AI at startup, set `vivadoProjectExplorer.ai.enabled` to `false` in VS Code settings.

## 6. Configure prompts and skills

The prompt and skill files in the release contain placeholders (for example, “需写入prompts”). They are not complete AI workflows. On first activation, Airtl copies them to this Windows-wide directory:

```text
C:\userconfig\rtlassistant\
```

Edit the files in this global directory. Airtl prefers these copies. Editing files inside the VSIX installation directory does not immediately update the global copies already installed on your computer.

### Task prompts: tell the AI what to do

Write a short task request in the corresponding file under `C:\userconfig\rtlassistant\tasks\`:

| Feature | File | Example task instruction |
| --- | --- | --- |
| Simulation | `tasks\simulate.md` | Run simulation for the current Vivado project and testbench, then report the results. |
| Synthesis | `tasks\synth.md` | Synthesize the current project and report resource and timing results. |
| Implementation | `tasks\impl.md` | Implement the current project and report routing and timing results. |
| Generate bitstream | `tasks\bit.md` | After implementation passes, generate the bitstream and report its output path. |
| Export simulation files | `tasks\export-to-sim.md` | Generate the files needed for simulation using the selected module and file list. |
| Fetch IP ports | `tasks\ip-port-fetch.md` | Find this IP's port definitions and update the port-direction data. |
| Explain a module | `tasks\module-explain.md` | Read the selected module source and explain its function and role in the project. |

### Skill files: tell the AI which steps, rules, and tools to follow

Write the procedure in `C:\userconfig\rtlassistant\skills\<skill-name>\SKILL.md`. For example, specify Vivado commands, which logs to inspect, how to diagnose failures, and what counts as completion. Scripts and reference files in the skill directory are copied as well.

Common skill directories are `simulate`, `synth`, `impl`, `bit`, `export-to-sim`, `ip-port-fetch`, and `module-explain`. For example, put the simulation task request in `tasks\simulate.md` and the detailed procedure in `skills\simulate\SKILL.md`.

You can also edit:

- `C:\userconfig\rtlassistant\system.md`: general rules for all AI features;
- `C:\userconfig\rtlassistant\flow.md`: conventions shared by Vivado workflows such as simulation, synthesis, and implementation.

Keep task prompts short and put reusable procedures in skills. Contact the developer if you need ready-made prompts or skills.

## 7. Configure other AI tools

OpenCode is the default built-in AI adapter. `vivadoProjectExplorer.ai.tool` also lists `dsh`, `zcode`, and `generic`, but they do not have built-in invocation protocols. Configure the matching `.command` setting with a command template for the target CLI before using one. Templates support `{message}`, `{cwd}`, `{systemFile}`, and `{session}`. Verify the command with the target tool's official documentation first.

## 8. Troubleshooting

- **The source tree or Block Design View is empty:** Make sure the project folder is open, select the right source under **工程来源** (Project Source), then refresh.
- **An AI workflow cannot find its tool:** Run `opencode` in the VS Code terminal, then connect a provider and select a model in OpenCode.
- **The AI receives the task but follows the wrong steps:** Check whether the corresponding files under `C:\userconfig\rtlassistant\tasks\` and `skills\` still contain placeholders.
- **Vivado cannot be found:** Check the `vivado` and `vivadoDir` values in `C:\userconfig\rtlassistant\config.json`.
- **An Airtl authorization message appears:** Check the network connection and the `Vivado Project Explorer` output channel. If the issue persists, send the machine ID and error details to the developer.
- **View diagnostic logs:** In VS Code, select **View → Output** and inspect `Vivado Project Explorer`, `Block Design`, or `Vivado Workflow`.
